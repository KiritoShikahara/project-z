==============================
  企業課題 ゲーム企画メモ
==============================

■ 開発概要
  ・エンジン：Unity
  ・締め切り：アルファ版の提出 12月中旬
  ・人数：プログラマー2 / マップ2 / デザイナー2
  ・最低ライン：敵なしでも成り立つこと
  ・アルファ版で必ず入れるもの
    → ワイヤー、オーラ
    → ゲームのベースとなるシステムは必ず完成させる
    → マップの作成はマップ担当に任せる（量はいったん保留）
  ・プログラマーの分担：仕様がすべて決まってから決める


■ 課題のルール
  ・日本語、英語などの文字は使用禁止
  ・記号、数字はOK
  ・作品展示会用に「文字表示 ON/OFF」があると助かるかも
    → 文字を出す場所は、最初から差し替えられる作りにしておく


■ プレイヤーアクション
  ・HPはある
    → 内部の数値とHPのUIは作っておく
    → 敵がいない場合、HPは画面に出さない
  【最初から使える】
    ・移動
    ・ジャンプ
    ・壁ジャンプ
    ・しゃがみ
    ・攻撃（仮）
      → ON/OFFで切り替えられるようにする
        敵がいるマップでは使う、いないマップでは使わない
  【あとで解放（順番は仮。アクションが増える可能性あり）】
    1. ワイヤーアクション
    2. オーラ（ブロックの破壊）

  ▼ ワイヤーの仕様
    ・どこにでも付けられる（付けられない壁・天井は除く）
    ・振り子のようにぶら下がる
    ・巻き取りが可能
    ・狙いの付け方：マウス / スティック方向
    ・届く長さ：作ってから調整
    ・空中ですぐ出せないようにするか：遊んでから調整

  ▼ オーラの仕様
    ・ボタンを押すとすぐ出る
    ・長押しで出し続けられる。離したらすぐ消える（連続使用OK）
    ・効果が届く範囲：作ってから調整
    ・壊せるブロックの見た目：Castlevania: Belmont's Curse を参考にする
      → 表面にひび割れがある壁、ブロック
      → 壊すのに必要な能力ごとに見た目を変える
        （参考作品では、聖なる光で壊すブロックや、
          高い所から叩きつけて壊す床などを見た目で区別している）
      → ひびがあっても壊れない壁が混ざっている


■ ダメージとやり直し
  ・トラップは基本的に即死
  ・再開は最後に使ったセーブポイントから
  ・死亡から再開までの演出：2秒程度（調整あり）
  ・壊したブロック、動かしたギミックは元に戻す（セーブにも残さない）
  ・「ギミックリセット」機能を用意するかは、あとで考える


■ ギミック
  ・セーブポイント（インタラクトで使う）
  ・ワイヤーを付けられない壁や天井
  ・一定区間を移動する回転刃


■ マップ仕様
  ・メトロイドのような、一つにつながったマップ
  ・マップ間の移動（Castlevania: Belmont's Curse のイメージ）
    → 光が出ている場所に入ると、次のマップに切り替わる
    → 行き来できる（戻れる）
    → マップの間に、セーブポイント用のマップを挟むこともある
  ・セーブポイント間のワープ（原神のようなファストトラベル）
    → 移動を楽にするためのもの
    → 解放したセーブポイント同士を移動できる
    → セーブポイントの間隔はマップ担当に任せる
  ・プレイヤーのギミックを解放していく
    → 解放するほど、行ける道が増える
  ・敵が出るマップと、ギミックのマップに分ける
    ※ 敵の作成は時間があれば
  ・奥行きを作る：3～5段階　作る際に自由に選択できるようにする
    ・「背景としての奥行き」と「マップとしての奥行き」を作れるようにする
      → 背景レイヤー：見た目だけ
      → マップレイヤー：プレイヤーが入れる
    ・例：手前で操作すると奥の背景が変わり、あとで通れるようになる
    ・プレイヤーはマップレイヤー間を移動することがある
      → 移動方法はいったん「扉」で考える

■ カメラ
  ・2Dゲーム。基本はプレイヤーを中心に追従
  ・ワイヤー使用時などはカメラを引く


■ 文字なしへの対応
  ・UIは記号で表す（HP、設定項目など）
  ・exitの「本当に閉じますか？」確認は、いったんなし
  ・操作説明：看板のようなものにボタンのアイコンを描いて知らせる


■ 操作デバイス
  ・キーボード / マウス / パッド に対応
  ・キー配置、キーコンフィグを入れる


■ セーブ
  ・基本は手動（セーブポイントでインタラクト）
  ・設定でオートセーブ ON/OFF
  ・保存する内容
    → 解放したアクション
    → 最後のセーブポイント
    → アイテム（アイテムを入れる場合）


■ 画面仕様
  1. タイトル画面
     ・「Any key」(仮)で進む
  2. スタート画面
     ・はじめから / つづきから
     ・マップ（ステージに入る）
       → 解放したセーブポイントの中から、開始場所を選べる
     ・設定
     ・exit（ゲームを閉じる）
  3. ゲーム画面
     ・解放したセーブポイント同士を移動できる
  4. メニュー画面（ゲーム中）
     ・開いている間はゲームを停止する
     ・設定
     ・exit（スタート画面に戻る）

  ▼ 設定画面の中身
    ・音量：BGM / 効果音
    ・キーコンフィグ
    ・画面サイズ
    ・表示モード：フルスクリーン / ウィンドウ など
    ・オートセーブ ON/OFF
    ・（文字表示 ON/OFF：展示会用、検討中）


■ マップエディタ
  ・マップ担当の人が使う
  ・形：Unityエディタ内のツール / ゲーム内（デバッグ中）で動くエディタ、どちらでもOK
  ・基本はマス目単位。マス目以外にも置けるようにしておきたい
  ・保存形式：プログラマーに任せる
    ※ ロードが重くならないように注意


■ プログラマーの担当
  ・プレイヤー、敵（仮）の挙動
  ・ギミックの作成
  ・マップを制作するための基本システム（マリオメーカーのイメージ）
  ・ロード、画面遷移などのシステム


■ 未決定
  ・クリア条件
  ・遊ぶ時間（ボリューム）
  ・ギミックリセット機能を入れるか
  ・アイテムを入れるか
  ・レイヤー間の移動方法（いったん扉）
  ・1マスのピクセル数（作るときに見て決める）

■ アート
  ・デザイナー：キャラ、背景の部品（建物、小物など）を作成。基本は自由に
  ・ほかの部分はUnityで作る（シェーダーなども使う）
  ・画面サイズ：よくあるゲームのサイズ（1920×1080、16:9）を基準にする
